# Research validation status

Updated 2026-09-29 after Phase 4 benchmark and independent review implementation.

## Implementation validation

175 automated tests pass for database preservation, provenance, six-source normalization, deterministic fusion, configuration/ablation isolation, graph semantics and validation, version/run isolation, independent evidence-backed review, server-side blinding, evaluation arithmetic, dataset separation, export integrity and audit trails. The frontend builds; the new benchmark/reviewer modules and API helper pass lint. A two-service HTTP smoke test on an isolated database copy exercises independent reviews, approval, evaluation and export, and verifies that reviewer credentials cannot access analysis results. All previous 33 table schemas/rows survive the Phase 4 additive migration; the recovered database now has 44 tables and all 11 benchmark tables remain empty. These checks demonstrate specified software behavior on test inputs. See `phase4_deliverables.md` for workflow, setup, evaluation definitions, backup paths and limitations; earlier phase documents record their respective scope and runtime baseline. Interactive browser acceptance and real-world APK/graph evaluation have not been performed.

The tests are SYNTHETIC implementation fixtures. They are not a benchmark, independently reviewed truth, or evidence of real-world detection accuracy. Exact source snapshots support traceability; a correct snapshot does not make an interpretation empirically correct.

## Empirical validation

**N/A — benchmark dataset not yet evaluated.**

The independent ground-truth/reviewer workflow, blinded reviewer API, evaluation engine and exports are implemented. There is still no independently reviewed REAL_WORLD dataset or completed empirical evaluation. Consequently empirical Precision, Recall, F1, TP, FP, FN, TN, false-positive/negative rates and reviewer agreement are unavailable. Synthetic test expectations verify arithmetic only; no substitute empirical numbers have been created.

The recovered database includes hand-authored example data and legacy automated results. Neither is automatically ground truth. A plausible APK hash, app name, existing report or automated finding does not establish benchmark eligibility.

Phase 4 fixes each dataset's label/category universe before review. The evaluation unit is a benchmark application version × finding label × data category, evaluated under one analysis configuration. Explicit negative decisions supply negative units; UNCERTAIN units are excluded and counted separately. Each reviewed unit requires independent evidence, separate observation and interpretation, access/transmission/disclosure statuses, reviewer identity and timestamps. Two distinct reviewers are required for approval; decision disagreements require a third independent review. Approval seals truth, and dataset freezing precedes evaluation. Evaluations require an explicit dataset type and exactly one matching analysis run for every version in the frozen cohort. REAL_WORLD selection never includes SYNTHETIC records.

Before collecting thesis results, establish the sampling frame, sample-size rationale, observation conditions, negative-label interpretation, exclusion criteria and reviewer training. Verify and retain actual APKs, document educational/free eligibility, curate prediction-free evidence, and complete independent human reviews. The software checks retained REAL_WORLD APK hashes and package/version metadata but cannot establish representativeness or reviewer independence by itself. Run A–E against the same frozen cohort, investigate false positives and false negatives, and archive the JSON/CSV exports and underlying artifacts. Do not run or report empirical evaluation with insufficient ground truth.

## Threats to validity

- **Construct validity:** permissions represent capabilities; string/API references do not prove execution; SDK/domain presence does not prove sensitive transmission. Unnecessary permissions require contextual justification.
- **Graph validity:** current code edges are REFERENCES_API_FOR, not ACCESSES_DATA. Shared category nodes do not establish source-to-sink flow. Transmission paths share a specific payload evidence anchor and remain qualified by annotation limitations. Orphan avoidance omits unjustified relations while retaining observations in provenance; graph size is not evidence coverage or accuracy. OBSERVED is a node role, not external artifact authentication.
- **Version identity:** graphs bind exact application record, APK hash, version name and run. Separate uploads are not automatically merged by package identity. Version metrics/change flags remain uncomputed for new graph-created version identities; graph isolation alone does not validate privacy-regression detection.
- **Source validity:** a policy document is a developer claim source, not behavior. Missing text is not denial. Data Safety retrieval and network capture are not currently implemented. Imports validate payload pointers, quoted claims and annotation metadata, but cannot authenticate a supplied capture hash or certify category/claim attribution. Unavailable evidence cannot become a negative label.
- **Static-analysis coverage:** obfuscation, reflection, native code, dynamic loading, dead code and string matching can cause false positives/negatives. No runtime or source-to-sink coverage is claimed.
- **Legacy contamination:** previous seeded and uploaded records include unsupported claims. They remain preserved and unverified; no retroactive truth or canonical findings were created from them.
- **Selection bias:** the recovered app list is not a representative educational-app benchmark. App/category/version and real APK provenance must be independently verified.
- **Reviewer bias and blinding:** the separate reviewer service returns an allowlisted raw-evidence packet and fixed protocol units; it has no analysis routes. The main API requires a researcher credential when research mode is configured and fails closed if assignments exist but that credential is removed. Review tokens do not authorize prediction endpoints. These boundaries cannot undo prior exposure or prevent a curator from placing interpretations inside free-text evidence. Curators/reviewers attest independence; use separate browser profiles, do not give reviewers the researcher key, and audit packet contents. Identities and independence remain researcher responsibilities. Remote deployment, credential lifecycle and human usability require additional acceptance work.
- **Scoring validity:** legacy risk/confidence values have no empirical calibration. Phase 2 Evidence Strength Scores and severity are explicit fixed heuristics. Permission corroboration concerns capability only. Scores are not violation probabilities and have not been empirically calibrated; repeated observations do not increase them. Phase 1 runs remain score-unassigned.
- **Ablation validity:** A–E vary evidence admission/fusion over a saved acquisition bundle, not execution of acquisition tools. Missing network/disclosure observations can make configurations semantically equivalent. Explicit imported context is held fixed. Legacy SDK-derived necessity interpretations are excluded to prevent cross-source leakage. No causal claim about detector accuracy follows from output differences.
- **LLM hallucination:** current report generation uses a deterministic linked-evidence template. Legacy LLM helpers and cached mock reports remain historical artifacts, not validated inference. Re-enabling model output requires source-grounding validation.
- **Reproducibility:** Phase 2 runs retain APK hash/version, source snapshots, tool versions/OS/Python, coverage, configuration/ontology/rule versions, replay source, input bundle and semantic hashes. Phase 4 adds frozen dataset/protocol/truth snapshots, independent evidence/reviews, predictions, per-version configuration and runtime metadata, evaluation version, timestamp and snapshot hashes. Unavailable Android tooling metadata is explicitly unknown. Rules/configurations are deterministic under tested input permutations and Python hash seeds. Researchers must still retain artifacts, capture conditions, source revisions and historical rule implementations. Windows/Python-specific dependency locks have not been validated on other platforms.
- **Statistical validity:** TP/FP/FN/TN and micro/per-label/macro metrics are implemented, but no empirical sample-size justification or confidence intervals have been established. Zero denominators yield unavailable values; macro averages use only defined labels and report their count. Category-level matching does not assess exact domains, call sites or individual transmission events. Report class support, excluded uncertain units and source coverage alongside metrics. Cohen's Kappa uses paired nominal POSITIVE/NEGATIVE/UNCERTAIN decisions and is unavailable for insufficient or degenerate pairs; prevalence and shared evidence can affect agreement. Different observation descriptions may accompany matching decisions and still need qualitative review. Software tests cannot resolve these empirical limitations.

Research readiness is not established by Phase 4 software completion. Runtime access instrumentation, a verified representative dataset, independent human reviews and real-world evaluation remain outstanding. The recovered database contains no benchmark study or manufactured ground truth. Empirical claims must wait for independently reviewed real applications and documented evaluation.
